# 田舎家 リニューアル提案

## 目的と範囲

鈴鹿市の麺処「田舎家（ぜいご）」のサイトを、料理のおいしさと店の落ち着きを伝えられる見た目に整えます。まず友人との相談に使える、上品な和の3パターンをローカルで体験できることを目的としています。

今回の成果物はReact + TypeScript + Viteのフロントエンドと、GitHub Pagesでのサンプル公開設定です。公開先は https://gerupon-lgtm.github.io/zeigo-sample/ です。実際の予約・問い合わせ受付、CMSの契約、ログイン、サーバーへの保存は次段階です。

## 3案の比較

| | A：白と墨 | B：藍と余韻 | C：木漏れ日 |
| --- | --- | --- | --- |
| 印象 | 端正、清潔、静かな老舗 | 落ち着き、会食、特別な食事 | 親しみ、家族、ふるさとの温かさ |
| 主な色 | 白 `#F8F8F3`、墨 `#292B26`、草灰 `#7B7653` | 藍 `#162C36`、生成り `#F2EFE5`、淡い金 `#BDAD7E` | 薄い紙色 `#F4F3E8`、深緑 `#354B3A`、葉色 `#738060` |
| 見出し | 縦書き、明朝、ゆったりした余白 | 横書き、明朝、大きな写真に重ねる | 横書き、明朝、柔らかな緑と料理写真 |
| PCの主役 | 左の縦書きと右のそば写真 | 一面の料理写真と藍の陰影 | 丸い上辺のうどん写真と外観の重なり |
| スマホ | 写真を先に、コピーは横書き | 写真上のコピーとすぐ押せる導線 | 料理・お店の写真を先に、あたたかいコピー |
| 提案の使い方 | 全体の第一候補 | 会席・御膳の利用を伸ばす方向 | 普段使い・家族連れを大切にする方向 |

最初の相談ではAを基準にし、Bの落ち着き、Cの親しみのどちらを強めたいかを比較すると決めやすくなります。実装は3案とも共通の内容データを使用しています。

## 情報の構成

```text
デザイン切替・比較・編集デモ（提案用）
店舗ロゴ / ナビゲーション / 電話
料理写真と短いメッセージ
営業時間 / 駐車場 / アクセスへの導線
店名の由来と、お店の想い
うどん / そば / 御膳の入口
カテゴリ切替式のお品書き / 税込価格
お知らせ / Instagram
外観写真 / 営業情報 / 電話 / 地図
フッター
```

PC（幅901px以上）は店舗ヘッダを画面上部に固定し、店舗紹介・お品書き・お知らせ・店舗アクセスへ移動できます。ジャンプ先は提案用バーと固定ヘッダの高さを考慮して、見出しを隠さず表示します。幅900px以下はハンバーガーメニューで同じセクションへ移動できます。スマートフォンは画面下に電話と地図を常設します。本文を妨げない余白を設けています。閲覧ダイアログはEscで閉じられ、キーボードのフォーカスを戻します。動きを減らすOS設定に対応し、本文へ移動できるリンクも設けています。

文字サイズは3案共通で、PC本文・品名18px、スマートフォン本文・品名16px、メインナビゲーション16px、価格24pxを基準にしています。注記・日付も14px以上とし、文字を大きくした分に合わせて行間、ナビゲーションの余白、お品書きの折り返しを調整しています。編集デモの入力欄も16pxです。

## 写真と価格を店舗側で更新する仕組み

創業については「昭和54年（1979年）創業。鈴鹿の地で、今年で〇年。」を3案共通で掲載しています。年数は閲覧時の日本時間から算出するため毎年の手動更新は不要です。創業日が未確認の間は年単位で計算し、正確な創業日を共通データに設定したら満周年の表示へ切り替えられます。「麺処」は現行サイトに記載があるため使用しています。

今回は操作の相談に使える編集デモを用意しました。写真3種・24品の価格・営業時間・定休日を変更し、3案へ反映できます。このブラウザだけの保存と、JSONによる受け渡しに対応しています。

実際の運用では、店舗向けの管理画面と保存先を追加します。表示側はすでに `Content` 型と共通JSONに分離しているため、デザインを変えずにCMSからのデータ読込へ置き換えられます。

```text
店舗スタッフ
    │ ログイン
    ▼
管理画面
    ├─ 写真を選ぶ → 画像保存 → 用途ごとの表示サイズを準備
    ├─ 価格を入力 → 税込価格を検証
    ├─ 営業情報・お知らせを入力
    └─ 下書き保存 → プレビュー → 公開
                              │
                              ▼
                    共通の店舗・メニューデータ
                              │
                              ▼
                    選んだデザインの公開サイト
```

実運用で必要な要素：

1. **管理者ログイン。** 店舗スタッフに編集権限を付与し、公開サイトの閲覧者と分ける。
2. **写真のアップロード。** 撮影画像を保存し、スマートフォン向けに適切な大きさへ変換。縦横比と代替テキストを管理する。
3. **構造化されたお品書き。** 商品名、カテゴリ、税込価格、表示順、提供中かどうかを個別項目で管理する。画像に焼き込まれた価格への依存を減らす。
4. **プレビューと公開。** 保存した下書きを確認し、公開ボタンで反映する。営業時間・価格の変更も同じ流れにする。
5. **履歴と復元。** 誤更新に備えて、誰がいつ何を変えたかを残し、前の状態へ戻せるようにする。
6. **バックアップ。** 画像と内容データを保管し、サイトの移行時にも持ち出せるようにする。

CMSやホスティングの製品選定は、現行契約、月額の許容額、更新頻度、編集人数、管理画面の使いやすさを確認してから決めます。現在は外部サービスを契約・接続していません。

本番では上部の提案ツールとlocalStorage編集デモを外し、更新用画面をログインが必要な別の画面にします。価格を更新したら紙のメニュー画像も一致するよう更新するか、サイト上のお品書きを文字情報へ統一します。

## 本番移行前の確認

営業時間の不一致、現在の税込価格、料理写真の原本、外観写真の文字なし原本、既存ロゴの扱い、予約の受付方法を店舗と確認します。根拠と不一致の詳細は `source-review.md` に記載しています。

## 検証

2026年10月3日にChromiumを使い、3案×5幅（320・390・768・1024・1440px）の横方向のはみ出しがないことを確認しました。スマートフォンメニュー、カテゴリ切替、お品書き原本6枚、お知らせ表示、比較画面、ブラウザ履歴での案の復元も操作しています。

編集デモは、価格保存、リロード後の保持、別案への反映、画像アップロード、JSON書き出し、不正JSONの拒否、初期化を確認。ブラウザのJavaScriptエラー・コンソールエラーは0件。PC・スマートフォンのスクリーンショットを `docs/previews/` に保存しています。

iOS Safari・Android実機での確認は未実施です。公開前の実機確認を次段階に含めます。

創業年数の計算は別途5件の自動テストで、2026年の47年表示、日本時間の年越し、創業当日の満周年更新、不正日付の拒否、日付未確認時の年単位表示を確認しています。
