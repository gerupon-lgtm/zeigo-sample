# お品書き・お知らせの編集仕様

更新日：2026年10月3日／サンプル版：20261003-4

## サンプルで試せること

3案は同じ内容データを使っています。そのため、編集内容を保存すると、どのデザインにも同じ変更が反映されます。

サンプルの保存先は、使用中のブラウザ内だけです。同じブラウザ・同じサイトのURLで開き直すと保存内容が残ります。別の端末やブラウザへの共有、実店舗サイトへの公開は行いません。ローカルURLとGitHub PagesのURLの保存内容も別です。

上部の「編集デモ」（スマートフォンでは鉛筆アイコン）から、次の4項目を切り替えます。

| 項目 | 操作 |
| --- | --- |
| お品書き | 品名・税込価格・カテゴリ・注記の変更、品の追加、非表示・再表示、カテゴリ内の表示順変更 |
| お知らせ | 記事の追加・編集、非表示・再表示、写真の追加・差し替え・取り外し、ピックアップ指定、不要記事の削除 |
| 写真 | メインのそば写真・うどん写真・外観写真の差し替え |
| 営業情報 | 通常の営業時間・土曜日の営業時間・定休日の変更 |

## お品書き

- カテゴリは「うどん・そば・丼／定食・寿司／御膳・会席」の5種類です。画面上の表記は「丼・定食」「寿司・御膳」です。
- 品名は100文字以内。税込価格は0〜1,000,000円の整数、注記は100文字以内です。
- 「品を追加する」で新しい品を作り、品名と価格を入力します。
- 「上へ・下へ」で、選んだカテゴリ内の順番を変更します。非表示の品も順番の対象に含みます。
- 非表示はデータを残す操作です。編集画面から「再表示する」で戻せます。
- 非表示の品はサイトに出しません。カテゴリ内の全品が非表示の場合は、現在掲載していない旨を表示します。
- 初期データは24品。サンプルの保存上限は全カテゴリ・非表示を合わせて199品です。

## お知らせの件数と表示順

**トップ表示は最大10件。保存は非表示を含めて最大20件です。** ピックアップも表示10件の中に含み、同じ記事を二重に掲載しません。

1. 非表示の記事を除きます。
2. ピックアップ指定の記事を先に、日付の新しい順に並べます。
3. 残りの記事を、日付の新しい順に並べます。
4. 合わせて先頭10件までを表示します。同じ指定・同じ日付なら、保存データの順番を維持します。

「表示対象」にしていても、順位が11件目以降の記事はトップに出ません。データは残るので、新しい記事を非表示にするなどで順位が繰り上がれば再び表示されます。未来の日付は表示順の指定として扱い、予約公開は行いません。

20件に達したら追加ボタンを無効にし、画面に案内します。古い記事を自動で消すことはありません。非表示にしても保存件数は減りません。不要になった記事は、削除確認後に取り除けます。削除は変更内容の確認と保存を終えてから反映されます。

## お知らせの内容とピックアップ

| 入力項目 | 条件・使い方 |
| --- | --- |
| 日付 | 実在する年月日。新規作成時は日本時間の当日 |
| 種類 | 必須・40文字以内。「お店から」「キャンペーン」「新メニュー」など自由に入力 |
| タイトル | 必須・140文字以内 |
| 本文 | 必須・5,000文字以内。改行も詳細画面に反映 |
| 写真 | 任意・1記事につき1枚。差し替え・取り外し可能 |
| 表示対象 | オフにすると非表示。オンに戻すと再び表示候補になる |
| ピックアップ | 写真・タイトル・本文の抜粋をカードで強調。写真なしでも利用可能 |

通常の記事は日付・種類・タイトルを一覧に表示します。ピックアップは優先表示するカードとして掲載し、選ぶと写真と本文の全文を表示します。非表示にした記事はピックアップにも出しません。

写真はJPEG・PNG・WebP形式、1枚1MB以下。画像として読み込めることを確認してから編集データに追加します。サンプルでは自動縮小・圧縮を行いません。

## 確認してから保存

編集中は、サイトへ反映しません。

1. 編集画面で内容を変更します。
2. 「変更を保存」で、変更した項目の変更前・変更後を確認します。写真も並べて確認できます。
3. 「編集へ戻る」で修正できます。
4. 「このブラウザに保存」で、保存成功後に3案へ反映します。

変更がなければ、その旨を表示します。確認・保存を終えずに編集画面を閉じると、未保存の編集内容は破棄します。ブラウザの保存容量が不足した場合は、以前の保存内容を保持し、編集中の内容も画面に残します。写真を小さくして再度保存するか、JSON（内容と写真をまとめたデータファイル）を書き出して保管できます。

「初期内容に戻す」は別途確認を挟み、このブラウザの保存内容と編集中の内容を初期データに戻します。

## データの持ち出し

- 「JSONを書き出す」で編集中の内容と写真をまとめて保管できます。
- 「JSONを読み込む」は40MB以下を受け付けます。20記事すべての写真とサイト写真を文字データに変換するとファイルが大きくなるため、この上限にしています。読み込んだ後も、確認画面を経て保存します。
- 形式、件数、価格、日付、識別番号の重複、画像形式などを検証します。
- 従来のサンプルJSONで新しい表示フラグがない場合は、表示対象として扱います。上限設定がない場合も表示10件・保存20件として扱います。この範囲に収まる従来の保存データを継続利用できます。
- 写真を多く含む場合、20件に達する前にブラウザの保存容量へ達することがあります。40MBの読込上限は、ブラウザに40MBを保存できることを保証するものではありません。これはローカル保存の制約です。本番では写真の保存先を別途用意する構成を検討します。

## 本番向けに検討する内容

メニュー名・価格・追加・非表示・再表示・表示順と、お知らせの追加・編集・非表示・再表示・ピックアップ、表示10件／保存20件を本番向けの機能要件として記録します。

本番では、別の管理画面へのログインと共有の保存先を用意し、変更確認後に公開できる構成を検討します。現在のサンプルにログイン、サーバー保存、公開履歴、共有編集、公開サイトへの書き込みは実装していません。本番の写真はスマートフォンで選びやすくするため、縮小・圧縮も検討します。

SNSとの連携は追って検討します。現在はInstagramへのリンクのみです。記事の共有リンク、投稿の表示、SNSへの同時投稿など、必要な連携の形を相談し、対象SNSの利用条件・費用を確認して決めます。自動投稿や同期は今回のサンプルには実装していません。
